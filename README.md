# END2END — Spectrogram → Action; CVNSS4.0 as a lookup lexicon

**A small, reproducible software proof of concept for Vietnamese edge speech research.** End-to-end refers here to a *direct feature-to-command decision*, **not** a production neural speech recognizer. The included experiment uses **artificial multitone waveforms, not speech recordings**. It does **not** establish Vietnamese ASR accuracy, accent generalization, TTS fidelity, ESP32-S3 memory use, hardware latency, or robot safety.

[Trang mô phỏng / GitHub Pages](https://xulytiengviet.github.io/end2end/docs/) · [Bản thảo preprint](paper/preprint.md) · [Phép thử](tests/test_pipeline.py) · [Nguồn CVNSS4.0](https://github.com/xulytiengviet/CVNSS4.0)

## Data path and claims

```text
PCM s16le 16 kHz (5,120 samples)
    → integer time-frequency features: 8 frames × 8 Goertzel bins
    → supervised nearest-centroid command classifier (direct feature → action label)
    → independent hand-coded spectral-template cross-check
    → fail-closed whitelist / margin threshold / NOOP
    → JSON action candidate; NEVER drives a motor

Unicode label → official audit-safe CVNSS4.0 converter → static reference lexicon
                                               ↓
                            A–Z + SPACE ↔ integer 0…26 ↔ 3 base-3 trits
```

**Critical distinction:** the handwritten dialect-number notation in the research draft (`trai3`, `ma4`...) is NOT the official CVNSS4.0 encoding. Real CVNSS4.0 is generated by the pinned converter. CVNSS4.0 encodes orthography, not IPA or regional pronunciation. Base27 pack/unpack is a lossless 27-symbol transport transform; it does **not** repair lossy CVNSS reverse ambiguities. A lexical whitelist cannot itself prove a command was spoken correctly. The spectral rule verifier shares the same signal, so correlated errors remain possible.

## 1. Reproduce with no Python dependencies

Requirements: Python ≥3.9; C11 GCC/Clang and Node.js for extra checks.

```bash
python3 experiment.py --seed 20261113 --train 8 --test 6
python3 -m unittest discover -s tests -v
gcc -O2 -std=c11 -Wall -Wextra -Werror firmware/infer.c -o infer
./infer --selftest
node scripts/build_lexicon.js
python3 -m http.server 8000
# open http://localhost:8000/docs/
```

`experiment.py` updates `results/report.json`, `results/predictions.json`, `results/model.json` and generates `firmware/model.h`. `scripts/build_lexicon.js` exports `data/lexicon.json` from `vendor/cvnss-converter.js`. The source codec is copied verbatim from `xulytiengviet/CVNSS4.0/assets/cvnss-converter.js`; its upstream copyright and documentation remain applicable. Pin the source by git commit hash before a release.

For an actual C/Python comparison, `tests/test_pipeline.py` produces new s16le PCM arrays, runs the C application and verifies all **64** features agree exactly (host compilation, *not* MCU run). `./infer --pcm file.raw` accepts exactly 5,120 signed 16-bit little-endian samples, prints its prediction, safety decision, margin, and features. No actuation is implemented.

## 2. Experimental design and reported metrics

- Six synthetic, finite command labels (`STOP`, `FORWARD`, `BACK`, `LEFT`, `RIGHT`, `LIGHT`) and out-of-vocabulary unknown patterns.
- Three **signal perturbation profiles**, which are **not** Vietnamese dialects, with independent train/test random seeds.
- Train: `6 classes × 3 profiles × 8 repeats = 144` artificial waveforms; Test: `7 labels × 3 profiles × 6 repeats = 126` distinct waveforms.
- Metrics: classification accuracy on known synthetic signals, hybrid correct acceptance, hybrid unknown false-accept, and known rejection. Detailed predictions and the fixed seed are exported as JSON.
- Never report these rates as ASR WER, acoustic generalization, calibration, or hardware performance.

## 3. Roadmap to empirical Vietnamese evidence

1. Register tasks, safety envelope, speaker/region/recording splits **before** evaluation; record informed-consent command speech by ≥3 regions, many speakers, devices and noise conditions.
2. Replace synthetic generator by real WAV loader; use speaker-disjoint train/dev/test; publish checksums and manifest. Include unknown commands and adversarial acoustic confusables.
3. Compare: A direct log-mel CNN/CRNN classifier; conventional ASR→intent; CVNSS-lookup-only; direct+lexicon; direct+spectral verifier. Calculate accuracy, FAR/FRR, WER where ASR exists, and confidence intervals.
4. Export trained int8/ternary weights and quantization calibration; track flash/RAM and output parity; measure wall-clock latency and energy on a named **actual ESP32-S3 board** with toolchain, firmware SHA and microphone configuration.
5. Integrate bounded runtime action constraints, independent sensors/estop, and human approval before real moving actuators. A simulated fail-closed gate is not a safety certificate.

## 4. File map

| File | Purpose |
|---|---|
| `experiment.py` | Deterministic waveform synthesizer, fixed-point spectral feature extraction, centroid training/evaluation, report export |
| `firmware/infer.c` | Portable C11 fixed-point feature/inference demo; no ESP-IDF dependencies and no physical actuation |
| `firmware/model.h` | Generated Q0…255 centroid features and signature patterns |
| `scripts/build_lexicon.js` | Rebuilds CVNSS4.0 dictionary from an upstream source converter |
| `vendor/cvnss-converter.js` | Original upstream audit-safe reference implementation |
| `docs/` | Offline-capable static research presentation and interactive **feature-level** simulation |
| `paper/preprint.md` | Preprint draft with falsifiable hypotheses, measured toy results and explicit limitations |
| `tests/` | 27-symbol bijection, fail-closed behavior, Python ↔ C parity tests |

## Optional real-audio neural path (not included in reported toy scores)

See [experiments/README.md](experiments/README.md) and [experiments/train_real.py](experiments/train_real.py). This optional PyTorch 64-bin log-mel CNN accepts an explicit speaker-disjoint manifest of real 16-kHz Vietnamese command WAV files. It exports a separate results/real/report.json and model.pt. **No real-speech metrics have been collected by this project release**; do not conflate optional training with the synthetic software benchmark.

## ESP-IDF wrapper

[firmware/esp32s3/](firmware/esp32s3/) contains a buildable-in-principle ESP32-S3 project that generates an artificial STOP waveform on device and calls the integer classifier. It has **not been flashed, cross-built, or benchmarked on a board**. It never accesses I2S microphones or motor actuators.
